# **<u>Project Report Format for CSE 4104 - Software Development Project – II</u>** 

## **Abstract (150–250 words)** 

A quick summary covering: 

- What problem the app solves 

- Main features 

- Tools/technologies used 

- Outcome/impact 

## **Table of Contents** 

List chapters/sections with page numbers. 

## **1. Introduction** 

Explain the project background: 

- 1.1 Project Overview 

- 1.2 Problem Statement 

- 1.3 Objectives / Goals 

- 1.4 Scope of the Project 

- 1.5 Target Users 

- 1.6 Limitations (if any) 

## **2. Literature Review / Related Work** 

Briefly describe: 

- similar apps already available 

- how your app is different/better 

- any research or references used 

## **3. Requirement Analysis** 

- **3.1 Functional Requirements** 

   - e.g., login, search, upload, notifications etc… 

- **3.2 Non-Functional Requirements** 

   - performance, security, usability, offline support etc… 

- **3.3 Hardware Requirements** 

   - phone specs / emulator requirements 

- **3.4 Software Requirements** 

- Android Studio version, SDK level, libraries, APIs, Firebase, etc. 

## **4. System Design** 

- **4.1 Architecture Diagram** 

   - e.g., MVVM / MVC / clean architecture 

- **4.2 Use Case Diagram** 

- **4.3 Activity Diagram / Flowchart** 

- **4.4 Database Design** 

   - ER diagram if using Room/Firebase/SQLite 

- **4.5 UI Design** 

   - wireframes or screen mockups 

(Insert diagrams and label them properly.) 

## **5. Implementation / Development** 

Explain how the app was built: 

- **5.1 Tools & Technologies** 

   - Flutter, Kotlin/Java, XML/Jetpack Compose, Firebase, APIs, libraries 

- **5.2 Module Description** 

   - describe main modules/features 

- **5.3 Key Code Snippets** 

   - only important parts, not full code 

- **5.4 Screenshots** 

   - add screenshots of working app with short captions 

## **6. Testing** 

- **6.1 Testing Strategy** 

   - unit testing, UI testing, manual testing 

- **6.2 Bugs Found & Fixes** 

short list of issues and solutions 

## **7. Results and Discussion** 

- final working output 

- performance observations 

- what went well and what didn’t 

- user feedback if collected 

## **8. Conclusion and Future Work** 

- **8.1 Conclusion** 

`o` summarize the achievement of objectives 

- **8.2 Future Enhancements** 

   - new features to add later 

   - improvements in UI/security/performance
